# GLAM Web Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the GLAM beauty & lifestyle marketplace (PRD v1.0, Phase 1 scope) as a responsive web app on Next.js + Supabase, runnable end to end from catalogue browse to order, return and refund.

**Architecture:** Next.js 16 App Router renders catalogue pages on the server and exposes JSON route handlers under `/api/*` for client interactions. Supabase Postgres holds all data with RLS; Supabase Auth (email OTP / magic link) manages sessions through `@supabase/ssr` cookies. Business logic (pricing, coupons, loyalty, order state machine, recommendations) lives in pure, unit-tested modules under `src/lib`; atomic order placement and stock decrement are Postgres functions called over RPC.

**Tech Stack:** Next.js 16.3, React 19, TypeScript 5, Tailwind CSS 4, `@supabase/supabase-js` 2, `@supabase/ssr`, zod 4, lucide-react, Vitest 5, Postgres 16 (local, for migration validation).

## Global Constraints

- Phase 1 scope only (spec §1). Phase 2/3 features are not built.
- Auth: Supabase Auth email OTP + magic link. Phone OTP, Google: configurable in dashboard, not required.
- Money: integer paise everywhere. Format with `formatINR(paise)` → `₹1,299`.
- Design tokens (PRD §12.2): primary `#DB2777`, secondary `#7C3AED`, text `#111827/#374151/#6B7280`, surface `#F9FAFB`, border `#E5E7EB`, success `#15803D`, warning `#B45309`, error `#DC2626`; radius 8px cards / 24px pills / 4px inputs; 4px spacing grid.
- Accessibility: 44px touch targets, visible focus rings, alt text on all images, `prefers-reduced-motion` respected, no colour-only meaning.
- Every route handler returns `{ error: { code, message } }` on failure with a proper status.
- Order statuses: `placed, processing, shipped, out_for_delivery, delivered, failed_delivery, cancelled, return_initiated, returned, refunded`.
- Return windows: beauty 30 days, fashion 14, wellness 7. COD limit ₹20,000. COD fee ₹40. Free delivery ≥ ₹999 or Silver+ tier. 1 point = ₹0.25. Points earn 1/₹10 × tier multiplier (1, 1.5, 2, 3).
- All business-logic modules have Vitest tests; `npm run typecheck && npm run lint && npm test && npm run build` must pass before completion.

### Task 2: Database schema, RLS, functions, seed

**Files:**
- Create: `supabase/migrations/0001_schema.sql`, `0002_rls.sql`, `0003_functions.sql`, `supabase/seed.sql`, `supabase/config.toml` (minimal), `scripts/db-validate.sh` (starts a throwaway local Postgres 16 cluster in scratch dir, creates `auth.users` stub table + `auth.uid()` stub, applies migrations and seed, runs smoke SQL, stops cluster)
- Create: `src/lib/supabase/types.ts` (hand-written `Database` types for tables used by the app)

**Produces:** every table in spec §3; functions:
- `place_order(p_user uuid, p_session text, p_payload jsonb) returns jsonb` — payload = `{items:[{variant_id, qty, unit_price, mrp, line_total}], address, pricing:{subtotal,item_discount,coupon_code,coupon_discount,points_redeemed,points_discount,delivery_fee,cod_fee,tax,total}, payment_method, delivery_slot, estimated_delivery, guest_email}`. Locks variants `FOR UPDATE`, raises `OUT_OF_STOCK:<sku>` if any short, decrements stock, inserts order/items/events/payment(initiated), increments coupon `used_count`, debits points, clears cart, returns `{order_id, order_number}`.
- `confirm_payment(p_order uuid, p_ref text)`: payment→success, order.payment_status→paid, event; for COD marks `cod_pending`.
- `fail_payment(p_order uuid)`: increments attempt; when attempts ≥3 cancels order and restores stock + points + coupon count.
- `cancel_order(p_order uuid, p_reason text)`: allowed only in `placed`/`processing`; restores stock, points, coupon; marks refund if paid (wallet credit).
- `advance_order(p_order uuid, p_status order_status, p_note text)`: validates transition table, sets timestamps, on `delivered` awards points (`award_points`) and sets `delivered_at`.
- `award_points(p_user uuid, p_delta int, p_reason text, p_ref_type text, p_ref_id uuid, p_expires timestamptz)` and `redeem_points(...)`: ledger insert + `profiles.points_balance` update.
- `recompute_product_rating(p_product uuid)`.
- Trigger `handle_new_user` on `auth.users` insert → `profiles` row with generated `referral_code` (`GLAM` + 6 upper alnum) + default wishlist collection + notification prefs.

Seed: 8 top categories (Skincare, Makeup, Haircare, Fragrance, Bath & Body, Men's Grooming, Wellness, Fashion) with 24 subcategories; 30 brands; ~200 products with 1–6 variants each (shades with hex for makeup, sizes for skincare/hair, sizes for fashion); 40 pincodes across 12 same-day cities + Tier 2; coupons (`WELCOME15`, `GLAM200`, `PRO10`, `FREESHIP`); 5 banners; 3 editorial cards; 1 active flash sale (12 products, ends 3 days from seed time). Images: `https://picsum.photos/seed/<sku>/800/800`.

Steps: write migrations → `scripts/db-validate.sh` runs clean → smoke SQL asserts counts (`select count(*) from products >= 180`) and `place_order` happy path + OOS failure → commit `feat(db): schema, rls, functions, seed`.

```ts
export type Tier = 'base' | 'silver' | 'gold' | 'platinum';
export interface PricingLineInput { variantId: string; productId: string; sku: string; qty: number; price: number; mrp: number; proPrice: number | null; flashPrice: number | null; offerType: 'none'|'bxgy'; offerBuy: number; offerGet: number; brandId: string; categoryId: string; categoryPath: string[]; }
export interface PricingContext { isPro: boolean; tier: Tier; pointsBalance: number; usePoints: boolean; coupon: CouponRecord | null; couponUserUses: number; pincode: PincodeRecord | null; paymentMethod: PaymentMethod | null; }
export interface PricingLine { variantId: string; qty: number; unitPrice: number; mrp: number; lineTotal: number; lineDiscount: number; priceSource: 'base'|'pro'|'flash'; offerLabel: string | null; }
export interface PricingResult { lines: PricingLine[]; subtotal: number; itemDiscount: number; couponCode: string | null; couponDiscount: number; couponError: string | null; pointsRedeemed: number; pointsDiscount: number; deliveryFee: number; deliveryLabel: string; codFee: number; tax: number; total: number; pointsToEarn: number; proSavings: number; freeDeliveryGap: number; }
export function priceCart(lines: PricingLineInput[], ctx: PricingContext): PricingResult;
export function validateCoupon(c: CouponRecord, ctx, subtotalAfterItems: number, lines): { ok: true; discount: number } | { ok: false; error: string };
export function deliveryFee(subtotal: number, tier: Tier, isPro: boolean, pincode: PincodeRecord | null): { fee: number; label: string };
export function tierForSpend(spendPaise: number): Tier;         // thresholds 10,000 / 30,000 / 75,000 rupees
export function pointsMultiplier(tier: Tier): number;            // 1, 1.5, 2, 3
export function pointsForOrder(eligiblePaise: number, tier: Tier): number; // floor(eligible/1000 * mult)
export const POINT_VALUE_PAISE = 25;
```
Rules: unit price = flash ?? (isPro ? min(pro, price) : price). BxGy: for every `offerBuy + offerGet` units, `offerGet` cheapest units free (same variant line). Coupon: `percent` → round(subtotal × value/100) capped `max_discount`; `flat` → value; `free_delivery` → delivery fee waived; scope filters apply to eligible lines only; rejects when `min_order` unmet, expired, not started, `pro_only` & !isPro, usage limits hit; error messages are user-facing. Points: redeem min(balance, floor((subtotal−discounts)/25)) when `usePoints`. Delivery: free if Silver+ or isPro or subtotal−discounts ≥ 99,900 paise, else pincode.delivery_fee (default 4,900), label `"Free"` / `"₹49"`. COD fee 4,000 when `paymentMethod==='cod'`. Tax 0 (inclusive). `pointsToEarn` on (subtotal − itemDiscount − couponDiscount − pointsDiscount). `freeDeliveryGap` = max(0, 99,900 − merch).

Steps: tests first for each rule (≥20 cases), implement, commit `feat(pricing): pricing engine, coupons, delivery, loyalty rules`.
